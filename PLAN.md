# World Cup 2026 Tracker — Build Plan

A zero-backend Ionic/Angular mobile app (Capacitor for Android) that tracks all 104
matches of the 2026 World Cup with simulated live data, local favorites, and a
swappable data layer ready for a production HTTP API.

---

## 1. Scaffolding

```bash
npx @ionic/cli start worldcup26 blank --type=angular --no-interactive   # standalone components by default
cd worldcup26
npm i @capacitor/android
npx cap add android
```

App id `com.worldcup26.tracker`, app name "World Cup 26". Capacitor config checked in;
the Android project is generated by `cap add android` and synced with `npx cap sync`.

## 2. Data model (`src/app/models/`)

- `Team`: `id`, `name`, `code` (FIFA trigram), `flag` (emoji), `group` (A–L).
- `Match`: `id`, `stage` (`'group' | 'r32' | 'r16' | 'qf' | 'sf' | 'third' | 'final'`),
  `group?`, `homeTeamId`, `awayTeamId` (or `null` = TBD knockout slot),
  `kickoffUtc` (ISO 8601 UTC string), `status` (`'upcoming' | 'live' | 'finished'`),
  `homeScore`, `awayScore`, `minute`, `venue`, `city`.
- `MatchEvent`: `matchId`, `minute`, `type` (`'kickoff' | 'goal' | 'fulltime'`),
  `teamId?`, `description` — the payload of `getLiveUpdates()`.

## 3. Swappable API layer (`src/app/services/`)

- `IWorldCupDataService` — abstract class declaring the contract:
  `getTeams()`, `getMatches()`, `getLiveUpdates()`, `getFavorites()`,
  `toggleFavorite(teamId)`, `isFavorite$` helpers as Observables.
- `WORLD_CUP_SERVICE = new InjectionToken<IWorldCupDataService>(...)`.
- All components inject `WORLD_CUP_SERVICE`; the only place the concrete class is
  named is `app.config.ts` / `main.ts` providers:
  `{ provide: WORLD_CUP_SERVICE, useClass: MockWorldCupService }`.
  Swapping to API-Football later = change `useClass` on this one line.

## 4. Mock data (`src/app/services/mock-data.ts`)

- 48 teams hand-written (12 groups × 4, mirroring the real 2026 field).
- 72 group matches **generated** by a round-robin helper (6 per group), not
  hand-typed literals; venues drawn from the real 16 host cities.
- 32 knockout matches (R32 16, R16 8, QF 4, SF 2, 3rd place, Final) with TBD slots
  labeled like "1A vs 2B"; total = 104.
- **Timeline anchored to "now"**: kickoffs are computed relative to app launch so the
  demo always has finished matches (last ~6 days), 2–3 matches live right now, and
  upcoming matches (~next 25 days). Source strings remain ISO 8601 UTC, satisfying
  the timezone requirement.
- Past-match final scores come from a tiny seeded PRNG (mulberry32 keyed by match id)
  so "Past Results" are stable across reloads instead of reshuffling.

## 5. MockWorldCupService — simulation + persistence

- State: `BehaviorSubject<Match[]>`, `BehaviorSubject<string[]>` (favorite team ids),
  `Subject<MatchEvent>` for live updates.
- One RxJS `interval(2500)` loop:
  - upcoming match whose kickoff ≤ now → `live`, emit `kickoff` event;
  - each live match advances ~2 sim-minutes per tick; random goal chance per tick
    (≈4%/team) → increment score, emit `goal` event;
  - minute ≥ 90 → `finished`, emit `fulltime` event.
- Favorites: read `localStorage['wc26.favorites']` at construction, write on every
  toggle. Anonymous, survives restarts. No login anywhere.

## 6. UI

**Structure** — two `ion-tabs`:
- **Matches** tab: toolbar with title + detected timezone chip
  (`Intl.DateTimeFormat().resolvedOptions().timeZone` + GMT offset), a
  "Favorites only" `ion-toggle`, an `ion-segment` (Upcoming / Live / Past), and a
  scrolling list of `match-card` components grouped by stage/day.
- **Teams** tab: 48 teams listed by group with star buttons (the "dedicated settings
  menu" for favorites).

**`match-card` component** (standalone, OnPush):
- `ion-card` with stage/group chip, venue+city, emoji flags, bold team codes,
  score (live/past) or localized kickoff time via Angular `date` pipe (upcoming),
  pulsing crimson `LIVE 67'` badge, tappable stars on each team.
- Favorited-team matches get a neon glowing border + gold badge.

**Theme** (`theme/variables.scss` + `global.scss`):
- Deep obsidian/pitch-black dark base, electric lime + stadium gold + magenta accents,
  subtle turf-green gradients on card headers.
- CSS keyframes: `pulse` for LIVE dot, `pop` (scale bounce) on favorite star tap.
- Ionic's built-in view transitions for navigation animation.

## 7. Verification

- `npm run build` (production) must pass clean.
- `npx cap sync android` to confirm the Android project wires up.
- Quick sanity check of the sim loop via a node-side run of the pure helpers.

# Overengineering review (simplifications adopted)

Reviewed the draft above; these cuts are now baked into the plan:

1. **No NgRx / state library.** Two `BehaviorSubject`s in one service is the whole
   state. Anything more is ceremony.
2. **No storage abstraction / Capacitor Preferences plugin.** The spec literally says
   HTML5 `localStorage`; a wrapper service around two `JSON.parse/stringify` calls
   would be pure indirection.
3. **Emoji flags, not 48 SVG assets.** Zero asset pipeline, perfect offline behavior,
   looks great at card sizes.
4. **Generate the 72 group fixtures, don't hand-write 104 literals.** A 15-line
   round-robin helper replaces ~800 lines of brittle data. Only the 48 teams and the
   knockout bracket shape are hand-authored.
5. **One Matches page with `ion-segment`, not three routed pages.** Three routes ×
   three components for the same list with a different filter is triple maintenance.
6. **Sim loop lives inside `MockWorldCupService`.** A separate "SimulationEngine"
   class sounded clean but adds a file boundary with exactly one consumer.
7. **`getLiveUpdates()` derives from the same tick**, not a fake-websocket layer.
8. **No separate facade between components and the token.** The injection token *is*
   the seam; wrapping it again defeats the point.
9. **Skipped**: i18n framework (Angular date pipe localizes times already), service
   worker, route guards, skeleton loaders (data is synchronous-local).
10. **Kept deliberately**: the 10-line seeded PRNG — without it every reload rewrites
    history in "Past Results", which reads as a bug.
